# Principales vectores de riesgo al conectar un LLM al entorno local

**Instrucciones escondidas en el contenido de un archivo** Ocurre cuando un archivo que procesa un comentario dentro de un repositorio clonado o la respuesta de una consulta web contiene texto redactado con intenciones maliciosas. Al leerlo, el modelo puede confundir ese contenido externo con una orden directa del usuario y ejecutar comandos o herramientas no autorizadas.

**Acceso fuera del directorio autorizado** Es el riesgo de que el modelo intente leer o explorar zonas sensibles del sistema de archivos que quedan fuera de la carpeta de trabajo; por ejemplo, acceder a llaves SSH, a archivos con credenciales de producción o a configuraciones del sistema operativo.

**Escritura o borrado no deseados.** Es la posibilidad de que el modelo, por una alucinación, una mala interpretación del contexto o una inyección de instrucciones, sobrescriba código válido, corrompa archivos del proyecto o elimine información crítica de forma irreversible.

## 2. Mecanismos y estrategias de mitigación

Para neutralizar estos riesgos, el ecosistema MCP implementa cuatro barreras de contención esenciales:

- **Confirmación humana** La aplicación Host intercepta las peticiones de las herramientas y exige una autorización explícita del usuario en pantalla antes de ejecutar cualquier acción que implique modificación, escritura o borrado en el disco. Ninguna acción destructiva o sensible se ejecuta de manera autónoma.

- **Alcance limitado** Delimitación estricta de las fronteras de ejecución mediante listas de acceso explícitas. El servidor MCP valida cada ruta y bloquea automáticamente cualquier intento de navegar o acceder a archivos fuera de las carpetas autorizadas.

- **Modo de solo lectura** Configuración del servidor en la que se desactivan o deshabilitan las herramientas de edición y borrado. Al operar exclusivamente con herramientas de lectura, se elimina técnicamente cualquier posibilidad de alterar el estado del sistema.

- **Revisar lo que expone el servidor.** Auditoría consciente por parte del desarrollador sobre los servidores MCP instalados y sus catálogos de herramientas expuestas. Consiste en verificar que el servidor provenga de fuentes confiables, que aplique el principio de mínimo privilegio y que no publique herramientas de sistema con capacidades más amplias de las estrictamente necesarias para la tarea.
