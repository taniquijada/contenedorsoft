# 3.¿Qué es una API y qué es MCP? 

## 1. ¿Qué es una API?

Una **API** (*Application Programming Interface*) es un contrato formal entre programas, estructurado bajo el modelo cliente-servidor. Quien programa decide de antemano qué endpoint se llama, cómo se invoca y en qué momento exacto del código se ejecuta. Funciona enviando una solicitud HTTP determinista (GET, POST, PUT, DELETE) con parámetros específicos para recibir una respuesta estructurada desde el servidor.

## 2. ¿Qué es MCP (*Model Context Protocol*)?

**MCP** es un protocolo abierto y estandarizado sobre JSON-RPC 2.0, diseñado para que los modelos de inteligencia artificial puedan interactuar con herramientas y fuentes de datos externas. Al iniciar la conexión ocurre un proceso de negociación inicial (*handshake*) en el que el servidor MCP publica un catálogo de herramientas, recursos y accesos disponibles. El modelo de IA descubre estas capacidades en tiempo de ejecución y decide autónomamente qué herramienta invocar, cuándo usarla y con qué parámetros, en función de lo que solicita el usuario.

## 3. Tabla comparativa: API vs. MCP

| Criterio / Aspecto | API Tradicional | MCP (*Model Context Protocol*) |
|---|---|---|
| **Quién decide qué se invoca** | El desarrollador humano, de forma explícita, al escribir el código de la aplicación. | El Modelo de Lenguaje (LLM), de manera autónoma, analizando el contexto y la petición del usuario. |
| **Cómo se descubren las capacidades** | Estática: se consulta la documentación o esquemas fijos definidos previamente (OpenAPI, Swagger, URLs fijas). | Dinámica: ocurre en tiempo de ejecución mediante el *handshake* inicial, donde el servidor envía el catálogo de herramientas disponibles. |
| **Acoplamiento** | Fuerte: el cliente debe programarse expresamente para adaptarse a la firma e interfaz concreta de cada API. | Débil / desacoplado: el cliente de IA solo debe entender el protocolo MCP estándar; cualquier servidor MCP compatible funcionará de inmediato. |
| **Formato de los mensajes** | Peticiones HTTP arbitrarias (REST, GraphQL, gRPC, SOAP) enviando estructuras JSON, XML o Protobuf. | Estándar JSON-RPC 2.0 a través de transportes estandarizados como stdio o HTTP con eventos enviados por el servidor (SSE). |
| **Autenticación y consentimiento** | Basado en tokens, API Keys o protocolos OAuth integrados en los encabezados HTTP. | Confirmación humana explícita (*human-in-the-loop*) en la interfaz del cliente antes de ejecutar herramientas o acceder a datos sensibles. |
| **Reutilización entre aplicaciones** | Específica para la aplicación en la cual el desarrollador decidió programar e integrar esa API. | Universal: un mismo servidor MCP (por ejemplo, para PostgreSQL o GitHub) se reutiliza sin modificar nada en cualquier entorno host (VS Code, Cursor, Claude Code, etc.). |

## 4. MCP no sustituye a las APIs: casi siempre envuelve una existente

MCP no es un reemplazo de las APIs tradicionales ni fue creado para sustituirlas en la arquitectura de software. MCP no sustituye las llamadas que una aplicación hace hacia su backend.

En la práctica, un servidor MCP casi siempre envuelve (*wrapper*) a una API que ya existe:

1. El modelo de IA interpreta el lenguaje natural y elige usar una herramienta del servidor MCP mediante mensajes en JSON-RPC 2.0.
2. El servidor MCP recibe la orden y realiza internamente la llamada HTTP real hacia la API REST, GraphQL o base de datos del servicio subyacente (como la API de GitHub, AWS o Google Maps).

Por lo tanto, MCP actúa como una capa de traducción intermedia para que las inteligencias artificiales puedan consumir y utilizar las APIs que ya existen.
