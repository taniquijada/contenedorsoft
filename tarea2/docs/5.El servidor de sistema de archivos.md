# 5.El servidor de sistema de archivos: herramientas y límites de contención

## 1. Servidor de referencia frente al protocolo MCP

- **Protocolo MCP.** Es la especificación técnica abierta que define el estándar de comunicación, los tipos de transporte sobre JSON-RPC 2.0 y la forma en que se negocian las primitivas (tools, resources, prompts).

- **Servidor de sistema de archivos.** No forma parte de la especificación del protocolo, sino que es uno de sus servidores de referencia oficiales. Es una aplicación concreta desarrollada en Node.js/TypeScript que demuestra cómo exponer el disco local respetando el protocolo MCP.

## 2. Herramientas que expone el servidor (*Tools*)

El servidor de archivos publica un catálogo de herramientas estandarizadas:

- **`read_file` y `read_multiple_files`.** Permiten leer el contenido en texto de uno o varios archivos para analizar código y contexto.

- **`write_file`.** Crea un archivo nuevo o sustituye por completo el contenido de un archivo existente.

- **`edit_file` / `apply_patch`.** Aplican modificaciones dirigidas a secciones específicas de un archivo existente, sin necesidad de reescribirlo por completo.

- **`create_directory` y `list_directory`.** Permiten crear carpetas e inspeccionar los elementos contenidos en una ruta.

- **`directory_tree`.** Genera una representación jerárquica en árbol de la estructura de carpetas y archivos del proyecto.

- **`move_file` y `search_files`.** Mueven o renombran archivos y buscan elementos por patrones dentro del proyecto.

- **`get_file_info`.** Extrae metadatos como tamaño, fechas de modificación y permisos.

## 3. Directorios permitidos (*allowedDirectories*) y riesgos de ejecución sin límite

**Mecanismo de contención.** Al arrancar el servidor, la aplicación Host le especifica explícitamente qué rutas del disco tiene autorizadas (*allowedDirectories*). Cada vez que el modelo intenta invocar una herramienta sobre una ruta, el servidor MCP verifica que esa ruta esté dentro del perímetro de seguridad y bloquea automáticamente cualquier intento de salto de directorio 

**¿Qué pasaría si no existiera ese límite?**

- **Fuga de datos confidenciales.** El modelo  podría leer claves privadas SSH, archivos con contraseñas de bases de datos o documentos personales en el disco.

- **Modificación o borrado destructivo.** Una alucinación del modelo o un comando equivocado podría alterar archivos del sistema operativo o eliminar carpetas críticas del usuario.

- **Exposición total a inyecciones indirectas.** Si un archivo leído por la IA contiene instrucciones maliciosas escondidas (*prompt injection*), el servidor las ejecutaría con acceso irrestricto sobre todo el sistema de archivos.
