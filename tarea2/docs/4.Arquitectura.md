# 4. Arquitectura de MCP: Host, Cliente y Servidor, primitivas y transportes

## 1. El modelo Host, Cliente y Servidor 

La arquitectura de MCP se divide en tres componentes clave, cada uno con responsabilidades bien delimitadas:

**MCP Host (Anfitrión).** Es la aplicación principal con la que interactúa el usuario y la que orquesta todo el entorno de inteligencia artificial.

Es el programa como Claude Desktop, Cursor, VS Code (con la extensión de MCP) o Claude Code. El Host se encarga de iniciar los procesos, coordinar la interfaz gráfica y solicitar la confirmación del usuario.

**MCP Client (Cliente).** Es el conector técnico interno (generalmente integrado dentro del Host) que mantiene una relación 1 a 1 mediante el protocolo MCP con un servidor específico.

**MCP Server (Servidor).** Es un programa ejecutable ligero y especializado que expone capacidades o datos específicos de un sistema.

- *¿Quién es en lo que instalas?* Es el paquete que descargas o ejecutas en segundo plano para conectar un servicio concreto.

## 2. Primitivas del Servidor (*Server Primitives*)

El servidor expone sus capacidades al modelo a través de tres primitivas principales:

- **Tools (Herramientas).** Son funciones ejecutables diseñadas para realizar acciones o causar efectos secundarios en el sistema (*side-effects*). Cuentan con un esquema definido en JSON Schema para sus parámetros 

- **Resources (Recursos).** Son fuentes de datos o documentos legibles que el servidor expone de forma pasiva, identificados por URIs (similares a endpoints GET o archivos en RESTcomo).Proveen contexto al modelo sin modificar el estado del sistema.

- **Prompts (Plantillas de entrada).** Son plantillas de mensajes y flujos de trabajo reutilizables, predefinidos por el servidor para guiar al usuario y al modelo en tareas específicas (por ejemplo, un prompt estructurado para revisar un *pull request* o analizar un error en la base de datos).

## 3. Primitivas del Cliente (*Client Primitives*)

El cliente también expone primitivas al servidor para delimitar su alcance y solicitar información:

- **Roots (Raíces / Directorios raíz).** Definen los límites espaciales del sistema de archivos y de los recursos a los que el cliente le otorga acceso al servidor. 

- **Elicitation (Solicitud interactiva de contexto).** Es la capacidad del protocolo que permite al cliente o al servidor solicitar activamente aclaraciones, confirmaciones de seguridad o datos adicionales al usuario en tiempo de ejecución, antes de proceder con una acción.

## 4. Los dos transportes principales

MCP abstrae la capa de red y permite que los mensajes en JSON-RPC 2.0 se transmitan a través de dos mecanismos:

**stdio (Standard Input/Output).**

- Funciona mediante comunicación inter-procesos (IPC) local. El Host lanza el proceso del Servidor en la misma máquina local y ambos se comunican a través de los canales estándar de entrada y salida (stdin / stdout).
- *Uso típico:* ideal para herramientas que corren localmente, como el servidor de sistema de archivos o conectores CLI locales.

**Streamable HTTP (HTTP con SSE – Server-Sent Events).**

- Diseñado para comunicación a través de la red. Utiliza peticiones HTTP POST enviadas desde el cliente hacia el servidor para enviar instrucciones, y una conexión SSE persistente para recibir respuestas e información en tiempo real desde el servidor.
- *Uso típico:* permite conectar la interfaz de IA con servidores MCP alojados en la nube, contenedores Docker o infraestructura remota.
